Read by the triage agent on every run. Edit this file to change what it takes.

Commits are cherry-picked individually; there is no merge base with upstream, so
every decision here is permanent until manually revisited.

## Decision rules, in order

1. **auto-take** — no judgement needed, take without asking:
   - Subject matches `Translated using Weblate` or `Updated translations`
   - Touches only `lib/l10n/*.arb`

2. **defer** — stop and report, never decide alone:
   - Touches any path under "Owned areas"
   - Cherry-pick conflicts in a non-generated file
   - `flutter analyze` regresses after the pick

3. **take** — the default for everything else:
   - Bug fixes, upstream refactors, Jellyfin API compatibility, dependency bumps
   - Applies cleanly and passes verification

4. **skip** — only with a recorded reason:
   - Reverts something we deliberately changed
   - Depends on an upstream feature we removed

## Generated files are never cherry-picked

`*.g.dart` and `*.freezed.dart` (95 files) are build artifacts committed
upstream. Picking them produces guaranteed conflicts and no information. The
`take` script drops them from every pick and regenerates via `build_runner`
instead. Same for `pubspec.lock` — regenerated by `flutter pub get`.

## Verification bar

`flutter analyze` must not regress, and `flutter test` must pass. Note the test
suite is 2 files — it proves almost nothing. Treat a green run as weak evidence.
A full `flutter build linux` is the real gate; it needs apt packages that are not
installed yet, so until then the fork's GitHub Actions build is the backstop.

## Skipped commits accumulate debt

Every `skip` is a future conflict: its descendants will not apply cleanly. When a
pick fails, check the ledger for a skipped ancestor before resolving by hand —
backfilling the skipped commit is usually correct and cheaper.
